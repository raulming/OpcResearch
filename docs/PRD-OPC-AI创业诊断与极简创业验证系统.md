# PRD：OPC AI 创业诊断与极简创业验证系统

版本：v0.1  
状态：研发规格草案  
产品阶段：MVP → 可商业化内测  
驱动方式：SDD（Spec-Driven Development，规格驱动开发）

## 1. 产品概述

### 1.1 产品定位

本产品是面向 OPC（One Person Company / 个体创业者 / 自由职业者 / 小团队主理人）的创业启动诊断与最小商业验证系统。

它不是一个泛 AI 聊天工具，而是一个帮助用户降低创业试错成本的结构化系统：

```text
自测诊断 → 阶段识别 → 风险提醒 → 工具箱生成验证计划 → 执行复盘 → 会员/陪跑转化
```

### 1.2 产品核心价值

帮助用户回答 4 个问题：

1. 我现在适不适合启动 OPC？
2. 我当前 AI 能力能支撑哪类创业动作？
3. 我的创业行为风格最容易卡在哪里？
4. 接下来 7 天我应该验证什么、找谁、怎么做？

### 1.3 产品形态

第一阶段采用：

- Web 自测页
- 结构化诊断报告
- 极简创业工具箱
- 免费完整体验一次
- 后台数据分析

第二阶段接入：

- AI Agent 报告生成
- 多轮追问
- 行动计划复盘
- 会员、积分、邀请体系

## 2. 目标用户

### 2.1 用户类型

| 用户类型 | 典型特征 | 核心诉求 |
|---|---|---|
| AI 初学者 | 想了解 AI 和副业机会 | 找方向、建立使用习惯 |
| 职场转型者 | 担心被替代，想发展副业 | 判断是否适合启动 |
| 自由职业者 | 有专业能力，但获客和交付不稳定 | 服务包、定价、流程化 |
| 内容创作者 | 有内容能力，但商业闭环弱 | 产品化、转化、验证 |
| 小微老板/管理者 | 想用 AI 降本增效 | 场景识别、流程改造 |
| 技术/产品人 | 会做工具，但商业验证弱 | 需求验证、MVP、获客 |

### 2.2 用户阶段

| 阶段 | 定义 | 产品建议 |
|---|---|---|
| 冲动探索型 | 想创业但客户、问题、付费均不清晰 | 先做社区探索和客户访谈 |
| 副业验证型 | 有初步方向，适合低成本验证 | 生成 7 天验证计划 |
| 服务启动型 | 有能力和客户线索，适合服务化 | 服务包、报价、SOP |
| 产品化阶段 | 已有交付经验，适合模板/工具/MVP | MVP、反馈收集、产品页 |
| 系统操盘型 | 有较强执行和 AI 能力 | 增长、自动化、复盘系统 |

## 3. 产品目标

### 3.1 MVP 目标

MVP 需要完成：

1. 用户完成三类自测。
2. 系统生成阶段诊断结果。
3. 用户可免费完整使用一次极简创业工具箱。
4. 系统生成一份《OPC 最小验证计划》。
5. 后台可查看自测数据、帮助意向、工具箱使用记录。

### 3.2 非目标

MVP 不做：

- 完整支付系统
- 完整会员中心
- 多租户企业后台
- 复杂 CRM
- 真正的长期 Agent 记忆
- 自动执行外部动作，如自动发消息、自动发布内容

## 6. 功能需求

### FR-001 三类自测

系统需支持三类自测：

1. OPC 启动准备度
2. AI 能力状态
3. 创业行为风格

当前 MVP 已实现前两项，下一阶段补充创业行为风格。

验收标准：

- 用户可在移动端完成所有题目。
- 每题为 1-5 分。
- 提交后计算总分和阶段。
- 所有结果保存到后台。

### FR-002 OPC 启动准备度测试

维度：

| 维度 | 判断内容 |
|---|---|
| 动机 | 是长期问题驱动还是短期焦虑 |
| 客户 | 是否知道服务谁 |
| 痛点 | 是否高频、刚需、有成本 |
| 反馈 | 是否和真实客户聊过 |
| 付费 | 是否知道付费理由和价格带 |
| 获客 | 是否能触达潜在客户 |
| 交付 | 是否能做成服务包或产品包 |
| 风险 | 是否有验证期和止损线 |

分层：

| 分数 | 阶段 |
|---|---|
| 8-16 | 冲动探索型 |
| 17-24 | 副业验证型 |
| 25-30 | 服务启动型 |
| 31-40 | 系统放大型 |

### FR-003 AI 能力状态测试

维度：

- 客户问题定义
- AI 协作能力
- 任务拆解能力
- 信息判断能力
- 内容/方案生产能力
- 服务包/报价/交付设计能力
- SOP 和模板沉淀能力
- 用户反馈/竞品分析能力
- 获客内容生产能力
- 7 天行动聚焦能力

分层：

| 分数 | 阶段 |
|---|---|
| 10-20 | 入门型 |
| 21-35 | 应用型 |
| 36-45 | 生产型 |
| 46-50 | 操盘型 |

### FR-004 创业行为风格测试

MVP+ 需新增 10 题行为风格测试。

维度：

| 维度 | 说明 |
|---|---|
| 执行稳定性 | 能否持续完成小任务 |
| 不确定性承受 | 能否接受慢反馈和失败 |
| 客户接触倾向 | 是否愿意主动访谈客户 |
| 复盘迭代能力 | 是否能基于反馈调整 |
| 自主驱动力 | 无监督时能否推进 |

分层：

| 分数 | 类型 |
|---|---|
| 10-22 | 灵感探索型 |
| 23-34 | 任务推进型 |
| 35-43 | 客户验证型 |
| 44-50 | 系统操盘型 |

### FR-005 诊断报告

诊断报告需展示：

- 启动准备度阶段
- AI 能力阶段
- 行为风格类型
- 最大风险点
- 当前最适合路径
- 第一份交付物
- 推荐工具箱入口

MVP 可规则生成，后续由 Agent 生成自然语言报告。

### FR-006 极简创业工具箱

工具箱定位：

帮助用户把想法转化为可执行的最小验证计划。

MVP 工具箱完整流程包含：

1. 想法验证
2. 客户访谈问题
3. 服务包/MVP 设计
4. 7 天行动计划
5. 继续/调整/暂停判断标准

输出：

《OPC 最小验证计划》

### FR-007 免费完整体验一次

规则：

- 已注册/留联系方式用户可免费完整使用工具箱一次。
- 同一联系方式只允许免费生成一次。
- 再次访问时展示历史结果。
- 未来可通过会员或积分继续生成。

验收标准：

- 未填写联系方式时不能领取免费体验。
- 第一次生成后保存记录。
- 第二次同联系方式请求返回历史结果，不重复生成。

### FR-008 会员、积分、邀请体系

MVP 可先设计规格，不强制开发支付。

会员层级：

| 层级 | 权限 |
|---|---|
| 游客 | 可浏览介绍，不保存结果 |
| 免费用户 | 自测、简版报告、工具箱完整体验一次 |
| 会员用户 | 多次生成、历史记录、导出、更多工具 |
| 专业用户 | 高级 Agent、深度追问、阶段复盘 |
| 陪跑用户 | 人工点评、社群、1v1 咨询 |

积分建议：

| 动作 | 积分 |
|---|---|
| 完整验证计划 | 80 |
| 想法验证器 | 20 |
| 客户访谈问题 | 15 |
| 服务包/MVP | 30 |
| 7 天计划 | 25 |
| 深度追问 | 5-10 |

邀请规则：

- 邀请人邀请朋友完成自测：+20 积分
- 被邀请人完成自测并留联系方式：邀请人额外 +30 积分
- 被邀请人付费：邀请人获得积分奖励或返佣

### FR-009 后台管理

后台需支持：

- 自测提交人数
- 启动准备度分布
- AI 能力分布
- 行为风格分布
- 帮助意向分布
- 工具箱使用次数
- 工具箱使用记录
- CSV 导出

MVP 后台不做复杂权限，仅 token 保护。

## 8A. 正式版技术架构

当前原型使用原生 Node + 本地 JSON，适合快速验证。但正式产品研发应按以下架构演进。

### 8A.1 推荐架构

```text
Web Frontend
  ↓
API Gateway / Backend App
  ↓
Domain Services
  ├─ Auth/User
  ├─ Assessment
  ├─ Report
  ├─ Toolbox
  ├─ Membership/Credit
  ├─ Invitation
  ├─ Admin Analytics
  └─ AI Orchestrator
  ↓
PostgreSQL / Redis / Object Storage
```

推荐技术选型：

| 层 | 选型 |
|---|---|
| 前端 | Next.js / React |
| 后端 | NestJS 或 FastAPI |
| 数据库 | PostgreSQL |
| 缓存/队列 | Redis |
| AI 编排 | 独立 AI Orchestrator 模块 |
| 分析 | PostHog / Metabase / 自建事件表 |
| 部署 | Docker + 云服务器，或 Vercel + 后端云服务 |

### 8A.2 模块边界

| 模块 | 职责 |
|---|---|
| Auth/User | 注册、登录、用户资料、角色 |
| Assessment | 题目、评分、维度、版本管理 |
| Report | 诊断报告生成、保存、导出 |
| Toolbox | 工具箱配置、运行记录、免费体验 |
| Credit | 积分余额、积分流水、扣减/返还 |
| Membership | 套餐、订阅、权限判断 |
| Invitation | 邀请码、邀请关系、奖励发放 |
| AI Orchestrator | Prompt、模型调用、结构化输出、成本记录 |
| Admin | 数据看板、用户筛选、运营配置 |

### 8A.3 AI Orchestrator 设计原则

AI Orchestrator 不直接改业务数据，只通过受控服务写入结果。

必须负责：

- Prompt 模板管理
- 模型路由
- JSON Schema 校验
- Token / 成本 / 延迟记录
- 失败重试与降级
- 敏感内容过滤
- AI 输出版本化
- AI 结果缓存

### 8A.4 版本化要求

以下内容必须版本化：

- 自测题目
- 评分规则
- 报告结构
- Prompt 模板
- 工具箱输出 Schema
- 会员权益规则
- 积分消耗规则

原因：用户历史报告需要可追溯，规则变化不能导致旧报告无法解释。

  "name": "明哥",

## 10. AI/Agent 设计规格

### 10.1 Agent 定位

Agent 不作为开放聊天机器人，而作为任务型创业教练：

- 诊断报告生成器
- 7 天验证计划生成器
- 客户访谈教练
- 服务包设计器
- 复盘助手

### 10.2 Agent 输入

Agent 输入必须结构化：

- 自测结果
- 用户职业
- 目标客户
- 痛点
- 触达渠道
- 可投入时间

## 15. 验收标准

MVP 验收通过条件：

1. 用户可在 5 分钟内完成自测并看到结果。
2. 用户可从结果页进入工具箱。
3. 用户可免费生成一份完整最小验证计划。
4. 同一联系方式不能重复领取免费体验。
5. 后台能看到自测数据和工具箱使用记录。
6. 部署在 `/opcresearch` 子路径时所有接口正常。
7. 用户数据文件不会被提交到 GitHub。
8. 移动端无明显布局错乱。
